<p>Cloud cost optimization often stops at the billing dashboard. Teams find an expensive service, review a chart, and ask someone to investigate the application code that caused the increase.</p><p>That process is slow because the bill shows <em>what</em> costs more, not always <em>which code</em> created the cost. Frugal takes a different approach: it connects source code, cloud, observability, and billing data to identify the code driving cloud and AI spend.</p><h2>Cost traps are usually code and configuration problems</h2><p>A cost trap is a technical decision that creates unnecessary or unexpected cloud spend. It might be an inefficient query, excessive logging, an oversized resource, repeated API calls, or an application workflow that uses more infrastructure than intended.</p><p>These issues can be difficult to see when cost data is separated from engineering context. A billing team may identify a rising service charge, while developers lack a clear path from that charge to the relevant repository, function, query, or API call.</p><p>Frugal helps connect those pieces so engineering teams can investigate costs in the same context where they maintain the software.</p><h2>From cloud bill to source code</h2><p>The core question is not simply, “Which cloud service is expensive?” It is, “Which part of our code is driving this cost, and what change can reduce it without compromising the product?”</p><p>That requires a connected view of:</p><ul><li><p><strong>Source code:</strong> the functions, services, queries, and workflows responsible for application behavior.</p></li><li><p><strong>Cloud data:</strong> the infrastructure and managed services used to run those workflows.</p></li><li><p><strong>Observability data:</strong> the operational signals that show usage, performance, and volume.</p></li><li><p><strong>Billing data:</strong> the actual cost patterns that need attention.</p></li></ul><p>For a practical example of how usage and implementation choices affect spend, see Frugal’s guide to <a href="https://frugal.co/blog/the-frugal-approach-to-gcp-cloud-monitoring-metrics-costs" rel="nofollow">GCP cloud monitoring metrics and costs</a>.</p><h2>Finding the cost traps worth fixing</h2><p>Not every optimization is equally valuable. A useful workflow prioritizes changes based on cost impact, confidence, and engineering effort.</p><p>Common cost traps include:</p><ul><li><p>High-volume operations that run more often than necessary.</p></li><li><p>Queries or data access patterns that use inefficient filters or indexes.</p></li><li><p>Verbose logs and metrics retained or emitted beyond their operational value.</p></li><li><p>Cloud resources sized for peak assumptions rather than observed demand.</p></li><li><p>AI API calls that use expensive models or send more context than the task requires.</p></li><li><p>Repeated calls that could be cached, batched, or moved to a more efficient workflow.</p></li></ul><p>Frugal’s overview of <a href="https://frugal.co/blog/top-10-cloud-cost-traps-we-saw-in-2025" rel="nofollow">cloud cost traps</a> provides additional context on the patterns teams should watch for.</p><h2>Turning findings into reviewable code fixes</h2><p>Identifying an opportunity is only the beginning. The change must still be implemented, tested, reviewed, and deployed by the team that owns the code.</p><p>Frugal generates reviewable pull requests aimed at reducing waste. This keeps the engineering team in control while moving cost optimization into an existing development workflow. Developers can inspect the proposed change, assess its effect on reliability and performance, and decide whether it is appropriate for the application.</p><p>A typical workflow looks like this:</p><ol><li><p>Frugal connects relevant cloud, observability, billing, and source-code data.</p></li><li><p>The platform identifies a cost pattern and traces it to the code or workflow contributing to the spend.</p></li><li><p>Frugal proposes a targeted change rather than a broad instruction to optimize everything.</p></li><li><p>The team reviews the pull request alongside normal engineering checks.</p></li><li><p>The approved change is merged, deployed, and monitored for its operational and financial effect.</p></li></ol><p>You can also read the <a href="https://frugal.co/blog/preview-of-frugal-code" rel="nofollow">preview of Frugal Code</a> for more detail on how code-level cost work can fit into development processes.</p><h2>Why code-level FinOps matters</h2><p>Cloud costs are created by technical behavior: the requests an application makes, the data it moves, the services it invokes, and the resources it keeps running. When cost ownership is separated from code ownership, waste can remain unresolved even when everyone agrees that the bill is too high.</p><p>Code-level FinOps gives engineering teams a more direct way to act. Instead of handing developers a monthly cost report, it gives them an actionable explanation and a change they can review.</p><blockquote><p>The goal is not to optimize everything. It is to find the changes that meaningfully reduce waste while preserving the product and the systems that support it.</p></blockquote><h2>A practical starting point</h2><p>Start with one high-impact service, workflow, or AI integration. Compare its billing trend with usage and observability data, then trace the most significant pattern back to the responsible code. Document the expected trade-offs and make the smallest safe change that can be tested and reviewed.</p><p>Frugal is built to make that process more connected. By finding cost traps and helping teams fix the code behind them, Frugal brings cost control closer to the decisions that create cloud and AI spend.</p><p>Explore more guidance in <a href="https://frugal.co/blog/why-not-just-optimize-everything" rel="nofollow">Why not just optimize everything</a>, or visit the <a href="https://frugal.co/landing-cloud-waste-audit" rel="nofollow">cloud waste audit</a> page to continue evaluating where your application may be creating avoidable cost.</p>
